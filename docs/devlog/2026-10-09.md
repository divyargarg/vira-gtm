# 2026-10-09 — Stage 1 kickoff

## What we did

- Agreed the Stage 1 plan: adapters → canonical record → normalize → dedup → SQLite → CLI.
- Agreed decisions (Divya, tech lead):
  - Code on GitHub, branch per change, review before merge.
  - Generic "manual CSV" adapter with a column-mapping file for segments 2 and 3 and the existing
    buyer tracker.
  - Split schema: `companies`, `contacts`, `company_sources`, plus a flat `buyers` view.
  - Auto-merge only on high confidence (same domain, or name score ≥ 92 in the same state);
    80–92 goes to a manual review queue.
  - Emails stored only when a source provides them, with provenance and `email_verified`.
- Step 0 done: uv project (Python 3.12), ruff, pytest, `vira version` / `vira info` CLI,
  `.env.example`, CLAUDE.md, docs vault skeleton, [[0001-sqlite-local-first]].

## What broke / open questions

- **ImportYeti terms of service.** Checked before designing the adapter. ImportYeti's terms
  (effective 2024-02-19) grant access only for personal, internal, non-commercial purposes, forbid
  compiling information for a commercial product, and forbid manual or automated data mining. The
  free site also has no official CSV export; the "exporters" that exist are unaffiliated
  extensions and scrapers. Using it to feed a commercial buyer pipeline conflicts with those terms
  as written. Not legal advice — needs Divya's decision before step 3 (see open options in the
  session summary). Source: https://www.importyeti.com/policies/terms
- GitHub repo not attached yet; work is committed locally on a feature branch.
